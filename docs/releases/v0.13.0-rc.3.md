## Phoenix v0.13.0-rc.3

This is a **public prerelease**, not the latest stable release. RC3 addresses an identified large-database migration scaling hazard discovered during an unsuccessful RC2 production upgrade. RC2's tag and downloadable assets remain unchanged; its dated upgrade warning remains available. Publication and production deployment are separate operations.

## Migration fix

- Incoming child foreign keys from `messages`, `steering_messages`, and `durable_turns` now have partial non-NULL indexes on `origin_subscription_event_id` before the outbox parent is rebuilt/dropped in migrations **119 and 120**. This avoids repeated unindexed child scans during SQLite's foreign-key processing. (#885)
- Forward migration **122** creates the same indexes idempotently for databases where the earlier migrations have already completed, including RC2 schemas. Historical and NULL rows, foreign-key integrity, transaction/ledger behavior, and the two rebuild paths have focused regression coverage.
- A deterministic fixture doubled in size used **157,419 → 628,107** VM steps for the unindexed DROP versus **1,044 → 2,004** with the indexes. These are synthetic operation-count results, not a production timing guarantee.
- A test fixture now retains its temporary directory for the lifetime of the returned database, preventing pool reconnects from losing that fixture's database path. This is test-only; it is not a runtime feature.

## RC2 upgrade incident and qualification boundary

The observed RC2 production upgrade from schema **118** did not complete migration **119** within the **120-second** activation/health window. The previous RC1 runtime was restored healthy at schema 118 without a database restore. Source inspection, synthetic reproduction, and read-only production query plans identify the quadratic incoming-FK scan hazard above; the exact failing production statement was not logged, so attribution of that historical timeout to the specific DROP phase remains conditional.

The integrated fix source `19635d2e725518aec17cbb49f168aa8caebe1864` passed full main CI and signed/notarized native preparation on both architectures ([private preparation](https://github.com/scottopell/phoenix-ide/actions/runs/38108607384)). That private candidate still reports `0.13.0-rc.2`, but it is **new-source qualification material**, not the published RC2 source or replacement RC2 bytes. Its native headless receipt does not establish migration performance on a production-sized existing database. An actual signed-candidate migration/startup check on an isolated immutable schema-118 production snapshot is a release-admission gate; no pass is claimed here before that check is recorded.

RC3 release builds must independently verify their freshly versioned source and bytes: Developer ID signing, hardened runtime, notarization, stapling, Gatekeeper, helper byte equality, both native isolated startup/authentication/database/graceful-stop checks, and the complete private asset set before publication. Public payloads remain exactly **eight assets plus `SHA256SUMS`**; sanitized native receipts remain separate Actions artifacts.

## Known limits and upgrading

- **Back up before upgrading.** Migrations are forward. Restoring an older binary/plist does not undo database mutations or guarantee that runtime can use the resulting database. Database rollback requires stopping Phoenix and restoring a matching backup with the older runtime.
- macOS GUI/clean-host and physical iPhone/Safari/installed-PWA checks remain user-deferred and pending. Native headless and isolated migration checks do not establish real-provider, GUI, published-updater, universal install/update, or rollback acceptance.
- Previous `298a` private core-journey/managed-helper-cycle evidence is not new RC3-byte lifecycle or GUI proof. The original stuck-tool-wait RCA remains unknown, and the small-scroll-jump reproduction item is not a claimed fix.
- Stable-only update discovery is unchanged; this candidate is prerelease/non-latest. Final stable promotion requires a new version and newly built/verified artifacts, not relabeling RC bytes.
- macOS artifacts are direct-distribution ZIPs, not a Mac App Store package, DMG, installer, or desktop updater. Native iOS/TestFlight and federation are outside this candidate's release gates.
