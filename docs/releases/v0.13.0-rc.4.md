## Phoenix v0.13.0-rc.4

This is a **public prerelease**, not the latest stable release. RC4 adds a standalone browser CLI, clearer conversation evidence, resource visibility, and conversation-creation and upgrade fixes. Publication and production deployment are separate operations.

## Standalone browser tools

Use Phoenix’s browser tools from another coding harness without running the Phoenix server. Download `phoenix-browser-<target>` for Apple Silicon (`aarch64-apple-darwin`), Intel macOS (`x86_64-apple-darwin`), or Linux (`aarch64-unknown-linux-musl` and `x86_64-unknown-linux-musl`). Verify the selected binary against `SHA256SUMS`, make it executable, and put it on your PATH as `phoenix-browser`.

```sh
export PHOENIX_BROWSER_SESSION="my-agent-unique-id"
phoenix-browser --json open http://localhost:3000
phoenix-browser snapshot --interactive
phoenix-browser type '#search' 'query' --clear
phoenix-browser key Enter
phoenix-browser console
phoenix-browser screenshot
phoenix-browser close
```

- `open` returns URL/title, interactive accessibility targets, and navigation console errors. Snapshot refs address exact nodes; refresh the snapshot when they expire. CSS selectors also work. Browser sessions persist across commands and expire after idle time. (#923, #925)
- CPU profiles, heap captures, traces, coverage, React diagnostics, and profiling scenarios use the existing Phoenix browser toolset. JSON output provides structured errors and artifact handles; uncertain transport failures never automatically replay actions. Schema/help and saved-profile analysis work without a browser.
- Four browser binaries join the existing server and desktop assets: **12 payloads plus `SHA256SUMS`, 13 assets total**. macOS browser executables are Developer ID signed and notarized. (#927)

See the [installation, session, profiling, and recovery guide](https://github.com/scottopell/phoenix-ide/blob/v0.13.0-rc.4/docs/phoenix-browser.md). Chrome may download on first use if no suitable local executable is available.

## Conversations and Global

- Conversation events use compact typed cards with expandable provenance and evidence. Supported inline conversation aliases navigate internally with a return path; Markdown links remain recognizable. Expandable disclosures retain surrounding Markdown context, including nested content and streaming code fences. (#918, #891, #890, #900)
- WorkScope resource sections show sampled CPU history and demand-sampled memory for live tracked Bash process groups. Unavailable measurements remain distinct from zero; these figures are not exhaustive host accounting. (#888)
- The local Global Coordinator has a persistent owned WorkScope and home at `<data_dir>/coordinator/`. Files survive ordinary conversation Close/Delete and are separate from transcript exports. (#910)
- Coordinator-only `remote_query_database` supports bounded read-only queries to explicitly enrolled Phoenix peers over authenticated HTTPS. This adds the capability; it does not claim live federation acceptance. (#860)

## Fixes and efficiency

- Restore durable asynchronous conversation creation with persisted provisioning, cancellation, and recovery. API clients observe the accepted request until it is ready. (#916)
- Preserve transcript continuity during finalization and incomplete Close. Keep ordinary Close fail-fast while hard-delete Bash cleanup remains best effort. (#890, #906)
- Bound startup search-index pruning and expose terminal reconciliation failures. Conversation pages select a bounded message page before loading large payloads. No production speedup figure is claimed. (#896, #895)
- Repair current-schema deployment preflight and tighten prepared activation, reservations, and cleanup. This does not establish production-upgrade or rollback acceptance for RC4. (#911, #919, #920)

## Upgrading and changed behavior

- **Back up before upgrading.** The migration registry extends through **128**, covering peer trust/addressing, wake retirement, Coordinator home ownership, and creation stages. Migrations move forward; older binaries are not guaranteed to accept the resulting database.
- **Durable wake execution is removed.** Historical records and evidence remain, but pending historical wakes no longer schedule observations or model turns. Already-admitted DirectTurns retain ordinary execution and settlement. (#894)
- Back up `<data_dir>/coordinator/` alongside SQLite while Phoenix is stopped. Database-only backups and transcript exports exclude those files; preserve the configured canonical home location.
- Gateway model aliases preserve canonical capability classification. `PHOENIX_LLM_REQUEST_MODELS` configures validated HTTP request-name overrides. Automatic `provider` header inference is removed; gateways requiring it must use `LLM_CUSTOM_HEADERS`. The native Codex bridge does not use these overrides. (#875)
- Close browser sessions before replacing the CLI; interoperability with older session daemons is not promised.
- Restoring an older executable does not undo database mutations. Manual rollback requires a stopped runtime and its matching database backup; qualified deployment paths have narrower explicit recovery rules.

## Qualification limits

macOS GUI/clean-host and physical iPhone/Safari/installed-PWA checks remain user-deferred and pending. Headless checks do not establish those gates, real-provider behavior, published-updater behavior, universal install/update, or rollback acceptance. This release makes no production-deployment claim.

Stable-only update discovery is unchanged. macOS app downloads remain direct-distribution ZIPs; native iOS/TestFlight and federation acceptance remain outside this candidate’s release gates.
