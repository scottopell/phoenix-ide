## Phoenix v0.13.0

Phoenix v0.13.0 is a direct-distribution release for macOS and Linux. Publishing downloads and activating an existing production installation are separate operations. The preparation checks below describe what was exercised; they do not claim that every installation or upgrade path was tested.

Stable v0.13.0 uses a new exact-version build and the publication checks described below; the earlier rc.4 preparation bytes are not final-version artifacts.

## Highlights

- **Continuous conversation history:** browse older transcript pages, follow historical conversation targets, preserve reading anchors and return navigation, and continue work without changing the conversation's permanent identity. The integrated source is delivered in [#932](https://github.com/scottopell/phoenix-ide/pull/932); qualification scope is below.
- **Clearer conversation evidence:** compact event cards and expandable provenance, typed internal citations, finalization/scroll corrections, and improved prose/table geometry. [#918](https://github.com/scottopell/phoenix-ide/pull/918), [#890](https://github.com/scottopell/phoenix-ide/pull/890), [#933](https://github.com/scottopell/phoenix-ide/pull/933), [#940](https://github.com/scottopell/phoenix-ide/pull/940)
- **Persistent local Global work:** the Global Coordinator has an owned WorkScope and home; delegated tasks expose their task/model context and WorkScope resource views show bounded process measurements. These are not exhaustive host accounting. [#910](https://github.com/scottopell/phoenix-ide/pull/910), [#950](https://github.com/scottopell/phoenix-ide/pull/950), [#888](https://github.com/scottopell/phoenix-ide/pull/888)
- **Standalone browser tools and paired macOS apps:** use browser commands from another coding harness without running the Phoenix server, or use the architecture-specific Phoenix.app ZIP with its embedded server helper. [Browser guide](https://github.com/scottopell/phoenix-ide/blob/v0.13.0/docs/phoenix-browser.md)

## Runtime and behavior changes

- Conversation creation is durable and asynchronous: observe an accepted request until it becomes ready rather than assuming immediate creation. Same-WorkScope continuation and post-continuation Bash execution have separate scoped acceptance; they do not imply universal lifecycle acceptance. [#916](https://github.com/scottopell/phoenix-ide/pull/916), [#926](https://github.com/scottopell/phoenix-ide/pull/926)
- Conversations have one editable human name. Readable `/c/` routes are allocated projections, separate from permanent product/transcript evidence identities. Duplicate names are allowed; **former slugs have no redirect or reservation guarantee**. [#951](https://github.com/scottopell/phoenix-ide/pull/951)
- Durable wake execution is removed. Historical records/evidence remain; already-admitted direct turns retain their ordinary execution and settlement. [#894](https://github.com/scottopell/phoenix-ide/pull/894)
- Gateway request-model overrides use `PHOENIX_LLM_REQUEST_MODELS`; automatic `provider` header inference is removed. Gateways requiring that header must configure `LLM_CUSTOM_HEADERS`. The native Codex bridge does not use these overrides. [#875](https://github.com/scottopell/phoenix-ide/pull/875)

## Distribution and installation boundary

The established release set is **13 assets**: four standalone server binaries, two Linux server debug binaries, four standalone `phoenix-browser` binaries, two macOS Phoenix.app ZIPs, and `SHA256SUMS` covering all12 payloads. Targets are Apple Silicon and Intel macOS, plus ARM64 and x86-64 Linux. Verify the exact selected payload against the manifest.

macOS ZIPs are direct-distribution archives—not a DMG, installer, App Store package, or automatic updater. Each app embeds the exact corresponding signed standalone helper. Both macOS architectures must pass Developer ID signing, notarization, stapling/validation, Gatekeeper, helper-byte identity and native isolated headless checks before publication.

The migration registry ends at **129**, whose naming transformation folds existing effective root names into one title and allocates deterministic readable routes. It does not promise former-slug aliases. The existing launchd helper admits the specific123→128 ordinary migration interval; it rejects128→129 under that path. This concrete helper limitation is distinct from the successful offline128→129 rehearsal below and from untested upgrade paths.

Migrations move forward; older binaries are not guaranteed to accept a changed database, and replacing a binary does not undo writes. Preserve the configured Coordinator home as well as the database when backing up an installation: database-only backups and transcript exports omit those files. No generic downgrade, live backup procedure, production snapshot restoration, or production activation guarantee is added here.

Close existing browser CLI sessions before replacing the CLI; interoperability with older session daemons is not promised. No Windows, native iOS/TestFlight, federation rollout, DMG, or new updater platform is included in this publication scope.

## Final publication checks

A stable release is a **new version and build**, never relabeled RC bytes. The resulting tagged main commit must build every required payload, repeat both native macOS supply-chain/headless gates and verify the exact13-name set, payload checksums, GitHub digests, tag/commit identity and stable/latest classification. Incomplete payloads remain in a private draft; reviewed notes are included when verified assets first become public. The public tag is created before builds; the draft is not a later human approval pause.

Publication does not itself perform or authorize a production replacement or database migration. The tested preparation/rehearsal evidence and the concrete helper limitation above are not a claim that every upgrade path has been verified.
