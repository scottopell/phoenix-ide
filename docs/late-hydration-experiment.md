# Isolated late-hydration query experiment

## Scope and identity

This is a fixture-only statement experiment, not a production query rewrite, end-to-end performance result, or historical-production causality claim. Production SQL and the existing browser replay binary are unchanged. A `cfg(test)` probe constructs an ordered `selected AS MATERIALIZED` CTE with the original topology, ceiling, cursor and lookahead predicates, then joins full message rows by globally unique ID in the same statement/transaction. The test build compares every parsed `(ordinal, Message)` field against control before passing candidate rows to the unchanged attachment hydrator. These dirty test-build timings are deliberately contaminated by executing both queries and must not be benchmarked.

## Decision

The experiment does not identify an exclusive sorter/table-access/CPU mechanism or explain the historical2.365945s span. No production rewrite/merge/deploy occurred. Keep the experiment separable from replay: promote only after direct generation/alignment/invalid-topology gates, then compare real shared-handler/browser behavior under an explicitly identified build. ## Correction provenance and missing causal test design

Independent read-only review of exact HEAD `124f96f1c0e7028fbd9db59668e5a033cad7713c` against `d63f657947b8e4e5c800107288acbc3a263165ad` found no blocking isolated SQL/hydration defect, but rejected the earlier report/doc claim of same-generation alignment retry. That claim described the two static handler alignment tests too strongly. This correction supersedes the gate-closure wording, not the immutable test logs or raw timing results. No task file containing that claim was found. Original timing-before-correctness ordering remains a violation; all eight pairs remain exploratory.

The actual owner is `api::transcript_observation::stable_transcript_read`, wrapping `TranscriptObservations::latest`/`before`, their aligned selection and tail reads. Its retry predicate is **generation inequality only**. There is no same-generation retry branch to qualify. `align_slice_start_to_render_unit` backfills through separate DB reads; the existing generation-injection hook runs after the entire read value is assembled, not between initial slice selection and alignment backfill.

Minimal test-only design (authored, not implemented or executed):

1. Add a one-shot, conversation-scoped `cfg(test)` hook immediately after initial slice selection/trimming and before `align_slice_start_to_render_unit`, for both latest and before paths. Keep hook types/storage/invocations absent from production builds; no new production retry policy.
2. In a disposable fixture, make the first slice require backfill. At that hook, await a transaction replacing the old history with a distinguishable new history and incrementing generation, completing its commit before alignment proceeds. Consume only the matching conversation's hook and release its storage borrow before awaiting; do not block the executor or spawn an unawaited writer. Force a nonempty post-reset prefix read and stay below the alignment ceiling, since read errors propagate rather than retry. Explicit hook completion, not sleeps, establishes ordering.
3. Read through the real `TranscriptObservations::latest`/`before` owner. Assert the hook was consumed, `StableTranscriptRead.attempts == 2`, generation advanced, and complete returned messages, aligned boundary, has_older and tail equal a fresh post-reset read. Pin explicit expected new message IDs, boundary, has_older and tail as well as fresh-read equality, so a shared implementation error cannot satisfy the oracle. Record that backfill actually read the replacement prefix, not merely that the hook ran. Confirm latest and exclusive-before behavior separately.
4. Independently inspect the hook placement/oracle before any host-admitted compilation. A source-reviewed but unrun test is not a passing gate. This proves generation-changing reset during alignment; it must not be relabelled same-generation retry.

Candidate-enabled API qualification is separately open: phoenix-db dependency `cfg(test)` is not enabled by API tests. If local candidate-path integration is requested, seek explicit approval for a bounded test-support-only route that exercises the candidate through the real dependency while leaving normal production SQL unchanged. That local qualification decision is distinct from approval to apply production SQL, and production application is distinct again from merge/deployment. None is authorized by the isolated experiment approval. No production constant switch, compiler run or measurement accompanies this correction/design.

A second independent read-only inspection checked this correction/design against the actual retry/alignment owner and found no blocking flaw. Its qualifications (awaited commit, scoped hook consumption without a borrowed cell across await, actual nonempty replacement-prefix observation, explicit expected IDs and bounded alignment) are incorporated above. This is design inspection only, not an implemented or passing causal test.
