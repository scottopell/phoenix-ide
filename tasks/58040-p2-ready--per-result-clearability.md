Tool::clearable() is a per-tool boolean, but some clearable tools have heterogeneous operations whose results are NOT re-queryable: bash run with wait_seconds=0 or a timeout returns a b-* handle that is the only reference for later peek/wait/kill, and the raw tmux tool is pass-through so callers can run mutating subcommands (send-keys, new-window, kill-window, kill-server) whose result is the only confirmation of a state-changing effect. Clearing those replaces the body with the generic placeholder, dropping irreplaceable info (tension with REQ-STR-002). The recency floor mitigates this for recent results; PR #330 accepted that mitigation. Improvement: result-level clearability — thread a runtime clearable flag on the tool result so bash can mark handle-minting runs (and raw tmux mutating subcommands) non-clearable while the safe majority of bash/tmux reads still clear.
