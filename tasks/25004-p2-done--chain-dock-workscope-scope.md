Chain-page work-scope dock shows wrong / stale inventory. Two findings deferred from the #231 codex review, now being fixed.

A. WRONG SCOPE (ChainWorkScopeDock, ChainPage.tsx). The dock resolves the chain ROOT's work_scope_key and queries that one scope, on the assumption "the chain's members share one WorkScope." That holds for Worktree/Branch/Work chains (all members share the worktree scope) but NOT for Direct-mode continuation chains: a Direct continuation keeps ConvMode::Direct, so WorkScope::resolve falls back to Conversation(<member id>) — each member has a DISTINCT scope. The active leaf's bash/tmux/browser then live under Conversation(leaf), while the dock queries Conversation(root) and shows an empty inventory. Fix: resolve the scope of the ACTIVE member (position == "latest", falling back to root for a single-member chain) rather than the root.

B. STALE COLLAPSED BADGE (WorkScopePanel standalone dock). The chain page omits liveInventory (no per-conversation SSE push channel), and useWorkScopeInventory's poll is gated on active = !collapsed. So a collapsed dock gets only the one initial fetch with no SSE and no poll: if a resource is live when the dock is collapsed and then exits / is reaped, the badge reports it running indefinitely until the user expands. Fix: the SSE-less standalone dock must keep a lightweight poll alive while collapsed so the badge can settle to 0 (the poll already self-limits via pollRunning = active && hasLiveResource, so it stops once nothing is live).

Also correct the REQ-WSUI-009 dock rationale comment / spec wording that asserts "members share one WorkScope, no per-member aggregation" — false for Direct chains.

RELATED (verify separately, may be its own task): the bash spec claims handles survive a continuation boundary because a continuation inherits its predecessor's WorkScope. For Direct chains the successor's scope (Conversation(leaf)) differs from the predecessor's (Conversation(root)), so unless a continuation rekeys the registry, Direct-chain handles do NOT actually survive the boundary — a spec-vs-reality gap distinct from this display fix.
