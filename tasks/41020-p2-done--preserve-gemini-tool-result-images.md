# Preserve Gemini screenshot and read_image results on the Chat route

Adversarial review of 878ccbb96da2177092ebe4e55370555cd40f10e6..256fc3fca91072f1f138e6ed1b2027b59f3f0145 confirmed a reachable visual-tool capability gap introduced by registering Gemini on Chat Completions. `browser_take_screenshot` and `read_image` return typed ToolOutput images; the runtime retains them as ContentBlock::ToolResult.images. `crates/phoenix-llm/src/openai.rs` logs and drops those images while translating tool results, so the normal Gemini follow-up sees only text. The separate compaction flattening path does not protect ordinary tool rounds.

A synthetic paired live gateway probe on 2026-11-20 established that Gemini's Chat route accepts tool-role content arrays containing text and image_url parts. With the same signed call and an inline magenta PNG, the image-preserving continuation returned magenta; the current text-only projection returned UNKNOWN. Native generateContent also accepted the image, so fixing this does not require switching API backends. Temporary evidence is /tmp/phoenix-gemini-adversarial-images.log; no provider signatures or credentials were retained in the log.

Implement a typed, route-qualified image-preserving tool-result representation. Preserve call IDs, error text, ordering, and private signatures; do not assume every Chat-compatible provider accepts images in tool-role content. Resolve the Chat Allium's generic image-dropping rule against the verified Google capability and browser REQ-BT-003/006. A normal tool loop using read_image must deliver pixels to Gemini, including after durable replay/retry. Add a regression that inspects the actual translated request and an opt-in live image exchange; retain honest logging on routes where the capability is unsupported.

## Completion evidence

Implemented in `1ec3d0f66`; ADR-272 records route qualification. The shared Chat projection preserves ordered images, tool IDs, and error text for built-in Gemini models without changing unqualified routes. It omits empty text parts on image-only results: a paired gateway probe confirmed that including an empty text part caused HTTP 400 while the same image alone succeeded.

Validation on 2026-11-20: all 495 LLM unit tests passed; all three provider-policy runtime tests passed, including image/signature preservation across SQLite reopen and retry; all four Gemini models identified the synthetic magenta image through the real adapter in both streaming modes.
