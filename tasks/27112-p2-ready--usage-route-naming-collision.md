The per-conversation usage surface has two routes with near-identical names but different shapes and purposes: `/api/conversations/:id/usage` returns `ConversationUsage { own, total }` (token totals for the conversation header badge) and was added Apr 28 in commit 9b88cbbda. `/api/usage/conversation/:id` returns `ConversationUsageDetail { root_conversation_id, totals, turns }` (per-turn cost-analytics drill-down for the /usage page) and was added Jun 16 in PR #307. Neither is deprecated; both are live and the UI uses both via distinct call-sites (getConversationUsage vs usageConversationDetail). The smell is the naming collision — the two strings are near-identical (`conversations/:id/usage` vs `usage/conversation/:id`) for different things. A cleaner split would group both under one prefix with distinct suffixes (e.g. `/api/conversations/:id/usage/totals` vs `/api/conversations/:id/usage/detail`, or both under `/api/usage/`). This is a rename refactor across the router, both handlers, both UI call-sites, and any specs/ADRs that reference the paths — no behavior change, just disambiguation. Do not remove either route; both have live consumers.
