# Make tool calls hard to hold wrong: operation contracts and remote inline research

## User outcome
An agent should readily form a valid `previous_transcripts` or `create_conversation` call, understand and recover from a rejected call without disclosure, and be able to delegate a saved-peer read-only SQL investigation to trusted Coordinator inline research. The user explicitly authorizes that child remote-read authority; it must not widen ordinary sub-agent or writing-conversation authority. Deliver usable installed tools and demonstrated journeys, not just a code review.

## Evidence and failure model
A bounded read-only sample of the latest 3,000 production message rows at `0.13.2-rc.2` / `1e5ae309f` had 306 `is_error` tool results. 214 were *synthetic server-restart interruptions* clustered in one hour across 214 conversations: exclude these from ordinary tool-misuse rates. The 52 `invalid previous_transcripts request` results were actual calls in eight conversations; the sampled calls supplied `cursor`, `query`, and `transcript_ref` together for `list`, `search`, or `read`. The advertised flat schema allows these combinations while `PreviousTranscriptsRequest` rejects them. `CreateConversation::input_schema` similarly advertises one permissive field set for `options`, `read`, `create`, while `CreateRequest` rejects cross-operation fields (including mutation-only `start` on reads/options). The Coordinator's observed rejected create calls are a seed, not proof of a server creation defect. `research_tools` registers local-only `QueryDatabase` although the Coordinator has the routed federated variant; current specs and ADR-222 explicitly require this restriction. The user rejects it for trusted inline research.

## Implementation scope
1. Investigate the actual provider-normalized/advertised schemas and arguments, including Anthropic's top-level union restriction and OpenAI behavior. Make operation-specific required and forbidden inputs truly hard for the model to mix up for both tools. Choose a provider-compatible representation (split capabilities or a tested nested operation union/another structurally precise design); do not merely add prose to the same permissive root or weaken runtime validation. If altering `previous_transcripts`' one-tool decision in ADR-051, record an explicit new decision and update its timeless normative requirements. Preserve host-bound predecessor scope, bounded cursors, clearability, creation's `request_id` replay/idempotency/defaults, canonical cwd and `start=submit_objective`; no rearming the already failed original request. Errors should identify the invalid operation/field or missing field and corrective shape without echoing sensitive arguments.
2. Extend **only trusted Coordinator inline research** `query_database` to accept the existing optional saved `instance` selector and use the same routed `FederatedQueryDatabase` implementation as the parent; keep exact `local`/omitted/null local, canonical saved-peer selection, typed source/destination identity, receiver-side read-only/credential-column denial, bounded output and no fallback after any remote failure. No arbitrary URL/credentials, peer enrollment, remote writes, general sub-agent or ProductConversation remote authority. Verify runtime registry construction and resumption so the permission derives from parent Coordinator identity rather than model-supplied input. Update inline research prompt/tool description for destination selection and untrusted rows.
3. Record the user's authority decision in a **new ADR** (do not rewrite ADR-222 history) and update `specs/remote-query-database/requirements.md`, `specs/federation/requirements.md`, and affected global-recall/conversation-retrieval/conversation-creation normative and executive docs as warranted. Ensure explicit SQL risk/authority boundary. Follow `specs/AUTHORING.md` preflight for spec edits.

## Regression and acceptance
- Provider-normalized schema tests and real dispatched-argument tests for valid and invalid variants of all `previous_transcripts` and `create_conversation` operations (including cross-op fields, missing required fields, null/wrong types, unknown fields); verify actionable non-echoing errors. Preserve authorization, immutable scope, nonblank/canonical validation and same-request creation reconciliation. Validate no job is admitted for invalid input and the original failed-job evidence is untouched.
- Registry and execution tests for trusted inline research: omitted/null/exact `local` run locally; explicit saved UUID/unambiguous name select the intended peer with identity; unknown/ambiguous/malformed/self, transport, auth, identity and remote SQL failures never fall back locally. Ordinary writing tools and ordinary sub-agents remain local-only. Cover reconstruction/resume and a real two-instance federated research query where supported; verify source provenance and untrusted-output handling. Replace the existing `coordinator_research_registry_queries_locally_and_rejects_instance_selection` regression with equivalent boundary and routing coverage rather than dropping it.
- Run focused tests and supported `./dev.py check`/hosted CI under source-custody/resource constraints. Obtain independent exact-HEAD review, then coordinate supported installation/delivery and verify the three user journeys against the installed runtime before reporting completion. Keep failures vs restart artifacts separate in evidence.
