M2 of the native HTTP MCP epic (tasks/58024): the Streamable HTTP transport substrate, per specs/mcp/ REQ-MCP-001/004/005/007/008. Stop skipping type:http entries in read_all_configs and classify them into McpServerConfig::Http (generic headers vs explicit StaticCred auth). Implement HttpTransport behind the M1 McpTransport trait: POST JSON-RPC with Accept listing application/json and text/event-stream, parsing both unary-JSON and SSE-stream responses into the same correlated result (server-initiated messages forwarded to the ServerMessageSink); 202-with-empty-body accepted for notifications; Mcp-Session-Id capture/echo plus DELETE on shutdown; negotiated MCP-Protocol-Version header on every post-initialize request; static bearer/header credentials attached to every request. Recovery: transport errors and session-expiry 404s rebuild the transport and re-initialize before one retry (reconnect, distinct from stdio respawn); 401/403 are surfaced, with the OAuth sub-lifecycle deferred to M3. Concurrent POSTs allowed — no per-server round-trip lock in the HTTP impl. Not a standalone release: OAuth (M3) is the first releasable unit. Tests run against a local scripted HTTP server.
