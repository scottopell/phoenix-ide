Build REQ-PROJ-037: "Request Changes" on a fork proposal promotes it into a fresh Explore conversation for agent-assisted iteration.

Context / why: a fork proposal is reviewed with only Approve / Dismiss today (REQ-PROJ-034). The proposer (a writing-mode origin — Work, Branch, or git-backed Direct, REQ-PROJ-033/036) is decoupled and has no attached LLM (REQ-PROJ-035), so "request changes" feedback cannot be delivered to it. Request Changes is offered for ANY pending fork proposal regardless of origin mode (wire the affordance/endpoint to the proposal, not to a Work-only path). Option C (chosen): promote the snapshot into a new Explore conversation seeded with the brief + the user's change note, and iterate via the existing Explore propose/feedback loop (REQ-PROJ-004). Spec is locked in (requirements REQ-PROJ-037, projects/design.md "Request Changes -> Explore refinement", Allium rule ForkProposalPromotedToExplore + `promoted` status). This task is the implementation.

Prerequisite: REQ-PROJ-033..036 (the fork feature itself) must be implemented first — this builds on the fork proposal record, the review surface, and the spawn/worktree machinery.

Scope:
- Add the `promoted` resolution + `refinement` conversation reference to the ForkProposal model and its persistence (migration if the proposals table is already shipped).
- Add the `/proposals/:id/request-changes` endpoint (free-text change note) and the `Effect::PromoteForkToExplore` executor handler, run under TASK_APPROVAL_MUTEX.
- Executor flow: derive the Explore conversation id DETERMINISTICALLY from `(proposal_id, "promote")` (NOT a fresh random id) so a crash before the `promoted` commit is re-drivable — the retry recomputes the same `.phoenix/worktrees/{refinement-id}` and adopts the orphan; the `"promote"` namespace keeps this disjoint from approval's `(proposal_id, "spawn")`. Create its worktree cut from main_ref (same fetch / freshest-commit-ish as approval); ensure the `tasks/` dir exists first (a plain-brief-only project may have none); write the snapshot body as an UNCOMMITTED draft UNDER `tasks/` (not at the brief's original path — Explore patch is tasks-scoped), TaskSource taskmd-vs-plain per REQ-PROJ-006; set `spawned_from_conversation_id = origin_id` (raw-id non-live breadcrumb); seed the Explore agent context with brief body + change note only. Persist the refinement conversation row AND the `promoted { refinement }` resolution in ONE DB transaction (no live child under a still-pending proposal). Then **dispatch the refinement's first LLM turn** (`LlmRequestDispatched`) so it starts iterating immediately rather than sitting idle.
- UI: third "Request Changes" action in the fork review surface (alongside Approve/Dismiss), with a note input. Withdraw the affordance once resolved.
- Refinement then uses the unchanged Explore->Work gateway (TaskApprovalExecuted / TaskApprovalFreshHandoffExecuted) — no second fork proposal, no path back to the origin.
- Lifecycle: `promoted` is terminal for the proposal; persists through origin terminal cleanup; removed only on origin hard delete (extend the existing cascades). The refinement Explore conversation has an independent lifecycle.
- Propagate the Allium rule to tests (/allium:propagate on ForkProposalPromotedToExplore).

Decoupling invariant to preserve: the origin is the proposer, never the iterator — the promotion must not mutate or notify it.
