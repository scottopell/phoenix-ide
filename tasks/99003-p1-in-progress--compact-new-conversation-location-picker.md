# Make `/new` usable with a compact location picker

## Observed journey
- Opening `/new` with many previously used repositories exposes a long, always-visible inventory of server-side paths ahead of the objective and Send action; the user says this makes starting a conversation unusable. The user wants to select a location without repeatedly staring at a giant folder list. ## Verified findings and contract
- `NewConversationPage.tsx` renders `ConversationSettings` separately for desktop and mobile, sharing one `useCreateConversation` state and placing desktop settings before the objective composer. Mobile keeps the objective composer bottom-anchored.
- `useCreateConversation` fetches recent management-root suggestions, persists selected `cwd` in `phoenix-last-cwd`, validates the directory, and submits the selected `cwd` with the objective/model/effort. `DirectoryPicker.tsx` renders **all** `recentPaths` in an unconditional `.directory-picker-recent` block before its editable path field; its directory-browser dropdown is separate and only appears on focus. The current backend response includes at most 20 existing management-root locations; an explicitly typed path can address locations outside this suggestion set. The recent block has no dedicated CSS cap/disclosure treatment.
- `specs/conversation-ui/requirements.md` REQ-PROJ-001A requires suggestions to be derived/deduplicated repository locations, selectable as working directories, not a user-owned Project catalog. `specs/projects/requirements.md` deprecates standalone Project naming and grouping. `specs/conversation-creation/requirements.md` preserves Git discovery/detached worktree provisioning versus non-Git Direct scope; do not equate selecting a location with guaranteed isolation or read-only operation. Directory picker tests cover validation but not recent-path selection/keyboard access; `/new` page tests cover creation/recovery but not suggestion clutter.

## Interaction map
Recent published conversation activity → management-root suggestion API → `useCreateConversation` → `NewConversationPage` → `ConversationSettings`/`SettingsFields` → `DirectoryPicker` → selected `cwd` → `useCreateConversation.handleSend` → existing creation endpoint; localStorage restores selected directory across visits. Recovery/start-over can also set the selection. This hotfix changes presentation/interaction at the picker boundary, not persistence or creation semantics.
