# Keep cancellation responsive during tool dispatch preparation

REQ-BED-005 requires cancellation within 100 ms and forbids queueing it behind completion of the current operation. At base `1e3122bd0726bf9a739d98ead4982dd2dd05f0b4`, `dispatch_tool_execution` still awaits originating request policy, catalog definitions, legacy scope and typed self-goal preparation in the owned event loop. Native preparation also awaits a parent-authority write and bounded request submission. A delayed preparation await can therefore keep a queued user-cancel from being selected and delay prevention of the planned launch. Native admission/activation response waiting already has selectable exact ownership from task75011.

Historical source proof on `9441cd2824324e53697df88f4e9db07f6de3980e` covered an inline native response wait as well. The commissioned implementation base has already removed that wait. The remaining current trace is `execute_authoritative_effect` -> awaited `dispatch_tool_execution` -> preparation reads, `prepare_self_goal`, or `start_spawn_agents_tool`'s parent-authority write/bounded send, before the surrounding loop selects user cancellation again. A deterministic timing regression for these remaining waits is part of this task.

Acceptance: hold a preparation read or bounded native submission at an explicit deterministic barrier, request cancellation, and prove the owned cancellation boundary settles promptly and prevents any later launch from the cancelled preparation. Retain an already-issued parent-authority write through its classified result rather than dropping it as a read. Preserve originating-request/schema admission, exact result ownership, committed child-admission reconciliation, and local SQLite authority classification/fail-stop. Do not solve delayed cancellation by replaying unknown-effect tools or weakening the 100-ms/nonqueued contract.

Related task14004 addresses head-of-line blocking and races inside the global child materialization handler; this task owns the distinct parent-conversation dispatch/preparation wait. Coordinate those seams without duplicating lifecycle authorities. The user commissioned this implementation after task75011 in a separate stacked PR.

Any preparation continuation must preserve immutable runtime/held-assistant/call origin across awaits, including failed policy/scope reads before an ordinary generation exists. Accept a classified failure only for its original active selection; a cancelled/replaced selection's late failure must not fail later work, even if a provider ID is reused. Actual unclassified local persistence authority still closes the shared fence regardless of selection age. The current inline await prevents this normal late interleaving; do not claim a current production stale-error failure from the proposed responsive target alone.

Preserve task75011's retained native handoff, unissued/issued/closed gate, affine manager lifecycle and classified closure/membership APIs. A spawn admission response is not activation: parent persistence proves the exact owner projection before releasing its activation capability. Cancellation and later admission join one operation; every admitted child remains owed until actual parent fan-in acceptance. Bounded submission must retain that same owner/control, not create another admission lifecycle. The pre-submission `establish_parent_reconcile_action` await is an actual SQLite write and requires retained authority until its result; a missing handoff alone does not prove no effects. Unclassified local authority follows REQ-BED-033 regardless of origin age. Do not race an outstanding command with an absence query, replay effects, change startup abandonment or introduce a durable store/recovery guarantee.

Also restore REQ-PERM-004's no-resource denial ordering at this same preparation boundary. The current code publishes start, allocates channel/token/generation, context and a spawned metrics writer before DenyGate; no tool task runs on denial, but call resources were already reserved. Evaluate Layer0 on the immutable selected origin first. A denial must return its paired ordinary error without an invocation/generation/context/start/metrics allocation; only the exact cleared checked-call proof admits those resources. Preserve originating-policy/schema reads and exact cancellation/stale handling for both clear and deny returns. Qualification should prove absence of those pre-clear effects with a denied input, not merely no ToolExecutor::execute call. This existing-source gap is separate from the unimplemented escalation counters; no permission exception or policy is expanded.
