# Avoid collapsing compact prose when it saves no space

## Problem

In compact conversation density, assistant text blocks shorter than `SIGNIFICANCE_THRESHOLD` currently collapse into a muted, italic one-line preview. This is helpful for multi-line or long-ish short prose, but it produces poor results for short single-paragraph messages whose collapsed preview is visually the same content as the expanded Markdown.

Example from the release workflow conversation:

> Branch protection requires required checks first, so I’ll enable auto-merge for the approved PR and monitor it.

The collapsed state shows the full sentence on one line, while the expanded state would also show the full sentence as one paragraph. The compact UI therefore adds friction and lower contrast without saving meaningful vertical space.

## Current heuristic

Compact assistant prose collapses when all of the following are true:

- conversation density is `compact`
- the block is an assistant `text` block
- `text.length < SIGNIFICANCE_THRESHOLD` (`280` chars)
- the text does not contain a Mermaid fence

Collapsed text is generated by `firstLineSummary(text, 140)`: first non-empty line, whitespace collapsed, ellipsized at 140 chars.

## Proposed solution

Replace the pure character-count collapse condition with a “does the preview actually hide content?” heuristic.

In compact mode, collapse a short assistant text block only when the collapsed preview would either:

1. omit additional non-empty lines, or
2. truncate a first line longer than the preview limit.

Short one-line prose that fits in the preview should render expanded by default, because the collapsed and expanded states occupy effectively the same space.

Suggested shape:

```ts
const COMPACT_TEXT_PREVIEW_LIMIT = 140;

function shouldCollapseCompactText(text: string): boolean {
  if (containsMermaidFence(text)) return false;
  if (isSignificantText(text)) return false;

  const nonEmptyLines = text.split('\n').filter((line) => line.trim());
  const firstLineFlat = (nonEmptyLines[0] ?? '').replace(/\s+/g, ' ').trim();
  const fullFlat = text.replace(/\s+/g, ' ').trim();

  const hidesAdditionalLines = nonEmptyLines.length > 1 && firstLineFlat !== fullFlat;
  const truncatesFirstLine = firstLineFlat.length > COMPACT_TEXT_PREVIEW_LIMIT;

  return hidesAdditionalLines || truncatesFirstLine;
}
```

Then have `AgentMessage` use `shouldCollapseCompactText(block.text)` instead of `!isSignificantText(block.text) && !containsMermaidFence(block.text)`.

## Expected behavior

| Text shape | Behavior |
| --- | --- |
| short one-line sentence under preview limit | render full |
| one-line text over preview limit but under significance threshold | collapse with ellipsis |
| short multi-line note where preview hides later lines | collapse |
| short Mermaid fence | render full |
| text at or above significance threshold | render full, unchanged |

## Tests

Add or update `MessageComponents.test.tsx` coverage for compact density:

- short one-line assistant prose renders as normal `.agent-text-block`, not `.agent-text-collapsed`
- one-line assistant prose over the preview limit but under `SIGNIFICANCE_THRESHOLD` still collapses
- short multi-line assistant prose still collapses when later lines are omitted
- existing short Mermaid compact behavior remains full-rendered

## Notes

Avoid a DOM measurement approach for now. Measuring expanded vs collapsed height would be viewport-accurate, but it is more complex and risky in the virtualized message list. The content-loss heuristic should capture the main UX issue with minimal rendering overhead.
