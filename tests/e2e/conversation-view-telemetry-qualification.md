## Isolated retrievable export

Start an ephemeral loopback-only OTLP HTTP/protobuf receiver alongside the existing owned processes, using `view_telemetry_sink.py` and the pinned official `opentelemetry-proto` decoder (no collector daemon), not Phoenix production VictoriaTraces. Set only synthetic `PHOENIX_TRACE_EXPORTER=otlp`, `OTEL_EXPORTER_OTLP_TRACES_PROTOCOL=http/protobuf`, a receiver-owned loopback `OTEL_EXPORTER_OTLP_TRACES_ENDPOINT`, and a unique service/run identity after the environment scrub. Do not restore inherited exporter headers, credentials or destinations. Fail setup if the receiver is unavailable or an endpoint is not loopback.

Retain exported trace bytes plus a decoded, allowlisted browser-span index under the existing private candidate artifact. Bound the receiver to 8 MiB total, 256 batches, 10,000 spans and the existing browser wall deadline; overflow is explicit failure, never silent truncation claimed as complete. Stop it with the existing owned-process teardown. The limits are harness budgets, not product guarantees. Wait for a bounded exporter flush and fail retrieval if expected identified spans are absent; HTTP 204 ingestion alone proves neither export nor retrieval. The sink persists each accepted protobuf batch and atomically replaces its decoded bounded index (not a cross-file atomic transaction); after drain/teardown `final_index` must reconcile raw batch counts/bytes and late error state before acceptance; `retrieve`, `validate_view` and `validate_correlations` check uniqueness, actual parent/trace identity, expected lifecycle/source/instance/timing fields, strict browser attribute projection and exact correlation set. The caller must wait for all expected exports under an absolute flush deadline and fail if absent; no daemon memory-only acceptance receipt is sufficient. Sink tests exercise official protobuf encoding plus actual loopback HTTP semantic retrieval and rejected transport.

Identify spans first by the synthetic service/run and the captured UUID `open.id`; inspect full traces only for those identified trace IDs. Require one `browser.conversation_view` per admitted reported journey, at most sixteen `browser.view_correlation` children and exact authoritative source/instance fields. The report trace need not equal an earlier API request trace: correlation children join them through opaque request/stream IDs and optional `trace` correlation entry. Validate finite API-response trace IDs against retrieved server traces when supplied. The server trace must contain a non-browser server span in a trace distinct from the report trace; a correlation that points only to the browser report itself is not evidence of server retrieval. Global initial `coordinator.history_open` must match its actual request `open.id`; older-page fetches must not become additional initial-open spans. A missing traceparent stays null, never fabricated.

## Browser cases and sampling

Reuse the two existing synthetic ordinary/Global aggregates and real HTTP/SSE, without route/response stubs. Observe report POST metadata/body and finite response headers only; never copy conversation response bodies into telemetry receipts. Distinct private sentinel transcript, breadcrumb, tool and route text must be absent from report JSON and allowlisted browser-span attributes. Actual synthetic history screenshots may remain in the separate existing history evidence, not in telemetry payloads.

Production sampling stays 25%. Do not add a public sampling knob or globally replace `Math.random` and claim unbiased application overhead. Pure tests already control admitted/sampled/unsampled cases through injected reporter randomness and transport. For real-browser runs, use fresh contexts and classify admission from actual correlated requests/report counters; bounded reruns obtain naturally sampled and unsampled observations. Retain every raw trial, including misses, failures and dropped reports. Maximum 64 fresh contexts, at most sixteen reports per case, existing five-minute browser/outer server bounds. Failure to obtain the minimum comparison cohorts within the budget is inconclusive, not a reason for unlimited retries or a sampling change.

Cases:

1. Ordinary and Global initial opens: ready report requires current visible transcript, visible actionable breadcrumb and actual current target or tail. Report marks are monotonic-client first observations; compare breadcrumb-minus-transcript frame estimates, not pixels or wall-clock server subtraction.
2. Exact predecessor/Back/reload: fresh journey IDs and request correlation; no readiness from navigation inventory, skeleton, empty virtual slots, hidden ancestors or stale target disposition. Use the existing real history checks as presentation ground truth.
3. Foreground/background: actual page visibility via a second tab where Chromium supports it. Record the browser's observed visibility; do not label synthetic dispatched events as physical suspension. No new readiness while hidden. Return foreground and verify current content before completion.
4. Standalone/BFCache resume: the synthetic hook tests prove event-state semantics; hosted Chromium must report actual standalone/BFCache capability. If unavailable, record uncovered status rather than labeling manually dispatched events genuine PWA/BFCache. Fresh resumed journey uses retained identity but fresh owning/rendered evidence, not old settlement marks.
5. Canceled/incomplete: leave a pending real admission or hide/unmount before readiness, then observe the best-effort terminal outcome. Use explicit lifecycle/navigation signals, not arbitrary sleeps to manufacture completion. A failed/offline send must stop within its three-second transport deadline with no retry/offline queue.
6. Collector negatives on the same disposable authenticated server: unknown/private fields, invalid UUID/enum, too many correlations, unbounded/censored-duration contradictions and oversized body are rejected and produce no accepted browser-view span. Unauthenticated request is denied. These are Phoenix API negatives, not malformed OTLP posts: a rejected OTLP transport intentionally fails the whole positive capture and belongs in a separate sink unit trial. Retain status and bounded schema diagnostics, never credentials.

## Lifecycle primitive contracts

`observePendingFiniteRequest(page, request, baseURL, {productConversationId})` must be armed from an actual sampled finite-request event before `request.timing().responseEnd` becomes nonnegative. It owns only its page listeners, not the page/context. `assertPending()` rejects completed/failed requests and already terminal journeys; completion uses the actual requestfinished/requestfailed identity. It captures bounded report metadata for that exact request correlation and fixture product, joins the POST to its own collector response and requires204. Unrelated successor reports remain the caller's separate inventory responsibility. Storage caps at two matching reports, one POST association and sixteen observed POSTs, each at most8KiB; overflow/error is retained for failure. The owner must retain capture until case drain, call `assertFinal()` before `close()` in finally, and include every observed journey (including any SPA successor) in the final export expectation inventory. `waitReport()` observes one accepted report, not proof against future duplicates; final sink reconciliation and owner drain remain mandatory.

`runPendingBackgroundRoundTrip({page,context,capture})` verifies the request is still pending *after* an actual hidden-visibility observation, awaits that finite completion while hidden, rejects any report before foreground, then obtains visible DOM readiness and a correlated accepted ready report. It checks unchanged URL/document and nonmissing readiness marks/positive background duration. Unsupported headless tab visibility remains unsupported. Generic DOM readiness is not a substitute for existing history/current target or tail ground truth; this helper alone does not prove every mark was first observed after foreground or settle the history gates.

`runPendingSPACancellation({page,baseURL,selector,capture})` rechecks pending state immediately before clicking a real same-origin navigable anchor, verifies changed destination with unchanged document time origin, and requires an actually accepted correlated canceled report. Ready/incomplete/cross-document pagehide and transient off-origin navigation fail. `runBFCacheRoundTrip(page,baseURL)` uses a real departure/Back and native pageshow persisted plus unchanged document time origin. A cold reload is unsupported, not a BFCache resume. The helper restores the starting candidate URL on failure without inventing restore evidence. It is only a capability witness; a fresh resumed journey/report with current owning-anchor evidence is still owed.

Browser evaluations/tab creation/front/cleanup have finite5s guards; response, readiness, navigation and report waits retain explicit5–10s guards. The primitives themselves create no contexts; the main driver now owns their lifecycle-stage contexts and absolute outer guard as detailed below. Failure receipts and cleanup remain mandatory. The original eighteen primitive contract tests passed locally, including precompletion/preterminal rejection, hidden early-ready rejection, unsupported visibility, wrong fixture attribution, failed/rejected response, late duplicate drain, transient off-origin and bounded BFCache restoration. They are mocks/contract tests, not actual Phoenix browser/export evidence. No physical PWA/mobile, final trace or overhead clearance is claimed.
